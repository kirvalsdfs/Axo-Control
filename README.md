# Керування програмами на ПК (блокування/дозвіл віддалено)

Проєкт з двох частин:

- **server/** — панель керування. Ставиться на один "адмінський" ПК
  (той, з якого ви керуєте всім). Показує всі підключені ПК, дозволяє
  блокувати/дозволяти програми — глобально (на всі ПК) або на конкретному ПК.
- **agent/** — маленька програма, яка ставиться на кожен ПК, де потрібно
  блокувати запуск програм. Раз на кілька секунд питає сервер "що зараз
  заборонено" і одразу завершує заборонені процеси.

Як це працює: агент не "забороняє запуск" на рівні системи наперед, а
миттєво (протягом ~1 секунди) завершує процес, якщо його назва є в
списку заблокованих. Для 15–30 звичайних ПК у мережі це найпростіший
надійний варіант, який не потребує складної системної інтеграції.

## 1. Встановлення сервера (на адмінському ПК)

```
cd server
pip install -r requirements.txt
set PC_CONTROL_API_KEY=якийсь-довгий-секретний-ключ
python app.py
```

Сервер підніметься на порту 8765. Дізнайтеся IP цього ПК у локальній мережі
(`ipconfig`, зазвичай щось типу 192.168.1.50) — він знадобиться для агентів.

Відкрийте у браузері: `http://<IP-адмінського-ПК>:8765` — це і є панель керування.

**Важливо:** обов'язково задайте свій `PC_CONTROL_API_KEY` (довгий випадковий
рядок), інакше будь-хто в мережі зможе керувати вашими ПК через цей самий
пароль-заглушку `change-me-please`.

Якщо на адмінському ПК є брандмауер Windows — дозвольте вхідні з'єднання на
порт 8765 (Windows Defender Firewall → Advanced settings → Inbound Rules).

## 2. Встановлення агента (на кожному з 15–30 ПК)

Скопіюйте папку `agent/` на ПК і виконайте:

```
cd agent
pip install -r requirements.txt
set PC_CONTROL_SERVER=http://<IP-адмінського-ПК>:8765
set PC_CONTROL_API_KEY=той самий ключ, що і на сервері
pythonw agent.py
```

`pythonw` (а не `python`) запускає без чорного консольного вікна.

### Автозапуск незалежно від користувача (рекомендовано)

У папці `agent/` є готовий `install_agent.ps1`, який робить усе одним
запуском: реєструє задачу, що стартує **"На старті системи"** (а не "при
вході користувача") від імені **SYSTEM** — тобто працює незалежно від того,
хто (чи чи взагалі хтось) залогінений на ПК, і сама перезапускається, якщо
процес завершиться.

1. Відкрийте `agent/install_agent.ps1` у текстовому редакторі й відредагуйте
   3 змінні на початку: `$ServerUrl` (адреса адмінського ПК),
   `$ApiKey` (той самий ключ, що на сервері), `$PythonExe` (шлях до
   встановленого `pythonw.exe`).
2. Клацніть правою кнопкою на файлі → **"Run with PowerShell"** — обов'язково
   від імені адміністратора (або запустіть з консолі PowerShell "Run as
   Administrator": `powershell -ExecutionPolicy Bypass -File install_agent.ps1`).
3. Скрипт сам створить системні змінні середовища й задачу в Планувальнику,
   одразу запустить агента і покаже його стан.

Перевірити, що спрацювало: на панелі (`http://<IP-адмінського-ПК>:8765`)
має з'явитися цей ПК у списку.

Щоб перевстановити (наприклад, змінили `$ServerUrl`) — просто запустіть
скрипт ще раз, він видалить стару задачу й створить нову.

<details>
<summary>Варіант вручну через Task Scheduler (якщо не хочете PowerShell)</summary>

1. Відкрийте **Task Scheduler** (Планувальник завдань).
2. **Create Task** (не Basic Task):
   - General: ім'я "PCControlAgent", вибрати **"Run whether user is logged
     on or not"**, обрати користувача **SYSTEM** (кнопка "Change User or
     Group" → ввести `SYSTEM`), "Run with highest privileges".
   - Triggers: **At startup** (НЕ "At log on" — інакше залежатиме від
     конкретного користувача).
   - Actions: Start a program →
     - Program: шлях до `pythonw.exe`
     - Arguments: шлях до `agent.py`
     - Start in: папка з агентом (щоб `agent_id.txt` зберігався поруч)
   - Settings: позначте "If the task fails, restart every 1 minute",
     "Restart up to 999 times".
3. Задайте змінні середовища `PC_CONTROL_SERVER` і `PC_CONTROL_API_KEY`
   **системно** (Панель керування → Система → Додаткові параметри системи →
   Змінні середовища → System variables), бо задача під SYSTEM не бачить
   змінні, задані звичайним `set` у консолі користувача.
</details>

### Масове розгортання на багато ПК

Щоб не робити це вручну 15–30 разів:
- Зберіть агента в один `.exe` (`pip install pyinstaller`, потім
  `pyinstaller --onefile --noconsole agent.py`) — тоді на цільових ПК не
  потрібен встановлений Python.
- Розкладіть готовий `.exe` + невеликий `.bat`-скрипт, що створює задачу в
  Task Scheduler (`schtasks /create ...`), по мережевій папці або через
  групову політику / скрипт входу, і запустіть на всіх ПК одним махом.

Якщо хочете, я можу підготувати такий `.bat`-скрипт для встановлення одною
командою — скажіть.

## 3. Користування

- Зайдіть на `http://<IP-адмінського-ПК>:8765`.
- У верхньому блоці — глобальний список заблокованих програм (діє одразу
  на всі ПК, що підключені).
- Нижче — список усіх ПК, з позначкою онлайн/офлайн. Натисніть "керувати",
  щоб заблокувати/дозволити програму саме на цьому одному ПК.
- Щоб **дозволити** програму — просто натисніть "✕" біля її назви у списку.
- Назву програми можна вводити як `chrome` або `chrome.exe` — без різниці.

## Блокування сайтів

Працює так само, як і блокування програм — на панелі є окремий блок
"Заблоковані сайти" (глобально, на всі ПК) і на сторінці кожного ПК
(тільки для нього). Вводите домен, наприклад `youtube.com` — не важливо,
писати з `https://`, `www.` чи ні, агент сам приведе до однакового вигляду.

Технічно це працює через файл `hosts` на клієнтському ПК — агент дописує
туди заблоковані домени так, щоб вони "вели в нікуди". Це:
- діє миттєво (перевірка при кожній синхронізації, тобто ~кожні 5 сек);
- не потребує жодних сертифікатів чи проксі;
- блокує домен повністю (усі сторінки на ньому), а не окремі слова в
  пошуку — для блокування ключових слів у пошуку потрібен принципово
  інший, набагато складніший підхід (проксі з розшифруванням HTTPS-трафіку
  та встановленням кореневого сертифіката на кожен ПК) — якщо це
  знадобиться пізніше, це окрема, більша задача.

**Важливо:** для запису у `hosts` агент потребує прав адміністратора/SYSTEM
— якщо ви налаштували автозапуск через `install_agent.ps1` (запускається
як SYSTEM), все спрацює само. Якщо агент запущено вручну в звичайній
консолі без прав адміна — у консолі з'явиться попередження, і сайти
блокуватись не будуть.

Якщо після блокування сайт все ще відкривається — найчастіша причина:
браузер закешував стару сторінку/DNS. Порадьте користувачу перезапустити
браузер, або самі зачекайте один цикл синхронізації (~5 сек) і спробуйте
в новій вкладці.

## Обмеження доступу до веб-панелі за IP

Щоб веб-панель (браузер) відкривалась тільки з певних IP-адрес — це
**не** стосується агентів (вони і далі підключаються з будь-якого ПК
через свій API-ключ, ніякого перенастроювання груп чи ПК не потрібно).

Перед запуском сервера задайте змінну середовища зі списком дозволених IP
через кому:

```
set PC_CONTROL_ADMIN_IPS=192.168.1.10,192.168.1.20
python app.py
```

- Якщо не задати — обмеження вимкнене, панель відкрита всім у мережі (як і
  раніше).
- `127.0.0.1` (сам сервер) завжди має доступ, незалежно від списку — щоб не
  заблокувати самого себе.
- Якщо адреса вашого ПК змінюється (DHCP) — краще налаштувати на роутері
  статичну (закріплену) IP-адресу для вашого ПК, інакше можете самі
  втратити доступ після перезавантаження роутера/ПК.

## Обмеження, про які варто знати

- Це блокування на рівні процесів (kill), а не на рівні прав доступу —
  досвідчений користувач теоретично може перейменувати exe-файл, щоб
  обійти блок. Для контролю над звичайними користувачами на ваших власних
  ПК цього достатньо; для захисту від навмисного обходу потрібен інший
  рівень (AppLocker/GPO), можу підказати за потреби.
- Агент має завершувати роботу лише реальних застосунків користувача —
  список `NEVER_KILL` у коді захищає базові системні процеси, але при
  додаванні правил не варто вписувати системні імена процесів.
